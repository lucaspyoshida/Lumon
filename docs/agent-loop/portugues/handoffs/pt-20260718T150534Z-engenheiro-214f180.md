## Alternativas consideradas

- **Estado V2 em `localStorage`:** rejeitado como escolha física deste plano; não oferece transação/CAS real para `revision`, migração e concorrência entre abas.
- **Tudo em IndexedDB, inclusive MP3:** rejeitado; Cache Storage serve `Response` same-origin e mantém mídia separada do estado/conteúdo.
- **Manifesto/itens em Cache Storage:** rejeitado como fonte canônica ativa; IndexedDB permite transação de catálogo/ponteiro e consultas sem transformar JSON em blob de estado.
- **Object URL/base64 para toda mídia:** rejeitado; aumenta cópia/heap e base64 é proibido. URL same-origin versionada é padrão.
- **Web Audio/SDK de player:** rejeitado; `HTMLAudioElement` único cobre o requisito com menos memória e dependências.
- **Preload de etapa/biblioteca em memória:** rejeitado; somente atual e próximo; pacote já preparado fica em armazenamento offline.
- **Hash JSON próprio/ad hoc:** rejeitado; RFC 8785 evita divergência entre build e browser.
- **Hash incluindo `manifestSha256`:** rejeitado por autorreferência.
- **Ativação copiando staging para cache final:** rejeitada; Cache Storage não renomeia atomicamente e a cópia duplica quota. Cache imutável fica invisível até o ponteiro.
- **Atualizar shell por arquivo com SWR:** rejeitado para o shell normativo futuro; pode misturar release. Instalação integral por release é verificável.
- **Limpar todo cache `lumon-*` em atualização:** rejeitado; shell, mídia, estado, sessão e versões referenciadas têm ciclos diferentes.
- **Lighthouse/framework adicional como base:** rejeitado por preferência; ferramentas atuais e scripts pequenos cobrem critérios iniciais.
